## 4. Ranked root causes and smallest fixes (all inside existing components)
RC1 (confirmed, code+logs) Terminal failure of the whole candidate when a unit-level defect survives repair: no last-resort withhold/degrade step. Fix: at the end of `_settle_s9` (cascade.py), for each remaining blocking finding whose origin is a single inherited unit or authored sentence, apply the existing deterministic lever with a recorded decision: (a) BC-05/BC-17 unit not carried: set VERIFIED_PRESERVE in a placeable section (zero-call restore already exists; extend its target selection to the nearest non-deterministic section, `PLACED` kinds); (b) BC-18/BC-14 stub on kept unit: `withheld_form` row/line/sentence, or OMIT_UNSUPPORTED citing the register row when nothing remains (record R14 drop with rule id, register row as evidence); (c) authored sentence flagged: reuse `recover_restating_sentences`-style sentence removal. Falsifier: replay each of the 28 stored failures zero-call (`recertify --all` style, plus stored call stores from artifacts if reachable) and require 0 provider calls, BC pass, no unit loss outside the recorded drop; measure unit-drop count per candidate. Properties: robust, universal, reliable. Risk: R14 (each drop must be recorded and calibrated; never silent), R9 (do not add wording about why), R10 (applies only on regeneration/recertify of a failing seal; never demotes: a passing seal stays untouched). Estimated recovery of the 28 latest: classes (a)+(b)+(c) cover ~21 of 28 (BC-17/05 ~9, BC-18 2, stub 2, authored sentence 6, BC-04/07/08/06 ~6 overlap); history: 20+15+9+9+6+7+6+4+5 of 73 failed runs contain these classes (about 55 of 73 touch at least one), but a run can contain several classes, so true recovery <= 55/73 and is unproven.
RC2 (confirmed code, partly pre-BL-170) job_error on one slot after the narrowed ask. Fix: in `run_job` fallthrough, before raising, let the `recover` hooks drop the single failing slot (authoring) or invalid fact id (planning) when that slot is not must-carry (`carried_units`); for must-carry slots fall to the inherited text (VERIFIED_PRESERVE, R14 record). Add the planning invalid-fact-id drop to `recover_planning_output`. Recovers 22/73 failed runs at most (job_error); 6 of 22 (spells x6) likely already fixed by BL-170; recovered share of remaining ~9. Falsifier: feed the stored rejected replies (`store.reject` files in the call store) to the new recover and require `_parse` to pass. Improves robust, reliable.
RC3 (confirmed) Model asked for a decision the check can already compute (10/22 unrepairable repairs). Fix: when `reject_printed_quote/reject_still_failing` messages name the keep action, apply it deterministically on the first refusal (skip ask2), saving calls and eliminating nondeterminism. Falsifier: replay the 10 logged cases. Improves repeatable, reliable.
RC4 (confirmed for 5 runs) 90-minute timeout kills candidate with rounds of 25-30 min. Fix: a wall-clock budget inside `run_cascade` that stops repair rounds at ~60 min and applies RC1 degrade, instead of being cancelled; timeout stays a safety net. This is a time-box not a spend budget (R45 unaffected). Falsifier: PDF Python replay. Improves robust. Cause of 25-min rounds unknown (see 5).
RC5 (hypothesis) reviewer-side contract failure on one unit blocks the seal; fix: a second narrowed re-ask for that unit only (different request, like authoring narrowing), still never dropping a finding. Independence risk low. Evidence: 1 run.
RC6 (probable) never-sealed cells re-roll because consumed inputs drift (toolchains, facts, policy components). Not robustness proper; flagged for repeatability lens.
