**Pass 3 addition — receipt coherence** (follow-up directive §3: "a receipt does not
automatically become authoritative because its JSON says it was generated by gatecli"):
`gateverify.receipt_is_coherent()` now schema-validates every accepted-looking receipt
(`schemas/receipt.schema.json` gained a required `scope.evaluated` field specifically so a
`--no-scope` run can never look identical to a properly-scoped one with zero violations) and
checks internal consistency — two identical clean passes, `scope.ok`, and a negative control
that was genuinely `applied` and genuinely `patch_applied_failed` with non-empty
`tree_changed`/`exit_codes`. `receipt_artifact_present()` additionally requires the receipt's
own `stdout.log` sibling to exist. A receipt failing either check is `INCOHERENT_RECEIPT` —
never silently trusted, never permanently stuck (it stays in the re-attemptable set). 10 new
tests (`tests/ops/test_receipt_coherence.py`) cover the five scenarios the directive named by
name: a forged positive receipt (3 variants: no clean passes, scope violation, schema
violation), missing negative-control evidence (3 variants: never applied, vacuous, empty
tree_changed), wrong generator, missing artifact, and an end-to-end `compute_rows()` proof that
an incoherent receipt neither counts as accepted nor blocks a downstream dependency from
retrying independently.

**All existing receipts were re-verified against this stricter schema** (not grandfathered in):
the schema change made every pre-pass-3 receipt technically non-conformant (missing
`scope.evaluated`), and each card was re-run through `gatecli.py verify` for real rather than
patched around.
